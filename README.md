# warp-vpn

WARP-in-WARP для Linux: VPN для всего компьютера и локальный HTTP/SOCKS-прокси
для отдельных программ. Собственный VPN-сервер не нужен.

Основная целевая система — **Void Linux**. Есть установка для **Arch Linux**
и модуль **NixOS**. Общий код написан на Python без сторонних Python-библиотек;
туннели обслуживает [Mihomo](https://github.com/MetaCubeX/mihomo), а регистрацию
устройств и поиск узлов выполняет [WARPSCOUT](https://github.com/vernette/warpscout).

Это независимые скрипты настройки, не официальный клиент Cloudflare или Amnezia.
Приложение Amnezia VPN и официальный WARP-клиент для этой схемы не требуются.

## Установка

| Система | Служба | Инструкция |
|---|---|---|
| Void Linux | runit | [Установка на Void](docs/void.md) |
| Arch Linux | systemd | [Установка на Arch](docs/arch.md) |
| NixOS | systemd через Nix-модуль | [Установка на NixOS](docs/nixos.md) |

Требуются Linux, Python 3.9+, curl, Mihomo с поддержкой AmneziaWG и WARPSCOUT
с экспортом двух туннелей в `mihomo-json`. Исходная рабочая схема проверена
с Mihomo **1.19.24** и WARPSCOUT **0.16.0**. Codex нужен только для `codex-warp`.
Для управления системной службой нужен root через `sudo`, `doas` или `pkexec`.
Установщик не добавляет правил беспарольного доступа.

После установки команд и зависимостей:

```sh
# Выполняется обычным пользователем. BY — пример своей страны.
warp-vpn setup --exclude-country BY

# Для Void/Arch: установить сгенерированные личные конфиги.
sudo warp-vpn install-config "$HOME/.local/share/warp-vpn"

warp-vpn proxy
warp-vpn status
```

Для NixOS установка приватных файлов описана отдельно в инструкции.
Поиск узлов может занять несколько минут. При существующем файле аккаунта
ключи используются повторно; автоматической ротации нет.

## Использование

```sh
warp-vpn on       # VPN для всего компьютера
warp-vpn proxy    # Только программы, настроенные на локальный прокси
warp-vpn off      # Выключить
warp-vpn restart  # Переподключить текущий режим
warp-vpn status   # Режим, страна выхода, узел Cloudflare
warp-vpn doctor   # Проверить наличие зависимостей и соединение

warp-run curl https://www.cloudflare.com/cdn-cgi/trace
warp-run git ls-remote https://github.com/MetaCubeX/mihomo.git HEAD

codex-warp
codex-warp resume --last
```

Оба режима используют **одну службу `warp-vpn`**. Включение полного VPN
переключает её в TUN-режим; `warp-run` и `codex-warp` переключают в прокси-режим.
При переключении текущие соединения через WARP прерываются.
Автозапуск после загрузки системы по умолчанию выключен.

HTTP и SOCKS5 доступны на `127.0.0.1:10881`. Прокси не доступен другим
компьютерам в локальной сети. Он остаётся включённым после закрытия Codex;
для остановки используйте `warp-vpn off`.

### Как связаны команды

```text
codex-warp / warp-run
          |
          +-- включает прокси-режим через общий код warp-vpn
          +-- задаёт HTTP_PROXY / HTTPS_PROXY / ALL_PROXY
          +-- запускает выбранную программу с этим окружением
                                      |
                               локальный Mihomo
                                      |
                          WARP внутри AmneziaWG/WARP
                                      |
                                   интернет
```

`codex-warp` — дополнительный запускатель Codex. Он использует тот же прокси,
что `warp-run`, и проверяет доступность адреса Codex перед открытием сессии.
При HTTP 403 один раз переподключает WARP. Если блокировка остаётся, сообщает
об ошибке. Проверка выполняется без токена авторизации и без запроса к модели;
HTTP 401 здесь означает, что запрос достиг адреса, требующего авторизации.
Проверка не подтверждает права аккаунта и не гарантирует работу дальнейшей сессии.

Настройки прокси наследуют дочерние программы. Это работает для curl, Git по
HTTPS и других клиентов, использующих proxy-переменные. Для поддерживающих
его версий Node.js задаётся `NODE_USE_ENV_PROXY=1`.
SSH, произвольный UDP и программы, игнорирующие прокси, этим способом не охватываются.
`localhost` исключён из проксирования. Уже открытые программы не меняют окружение.

## Свои ключи и выбор узлов

Каждый пользователь получает **собственные два WARP-устройства**. Готовых
аккаунтов или ключей в репозитории нет. По умолчанию регистрация не использует
сторонний relay; при проблемах смотрите [диагностику](docs/troubleshooting.md).

Можно выбрать страну внешнего узла или указать ранее проверенные адреса:

```sh
warp-vpn setup --country PL
# Адреса ниже — документационные примеры; замените найденными узлами.
warp-vpn setup --outer 192.0.2.1:2408 --inner 198.51.100.1:2408
```

Если конфиги уже существуют, для повторного подбора нужен `--force`.
Перед сканированием с теми же ключами остановите работающий WARP:
устройство нельзя одновременно использовать в независимых туннелях.

Приватные данные сохраняются в `~/.local/share/warp-vpn` с правами `0700/0600`.
Установленные конфиги — `/etc/warp-vpn/tun.json` и `proxy.json`, права `0600`.
Пути к исполняемым файлам и порт хранятся в `settings.json`, без секретов.

## Ограничения и проверенность

- Зарубежный узел Cloudflare **не гарантирует постоянную страну выхода**.
  `colo=WAW` и `loc=PL` — разные показатели. Встречался случай возврата `loc=BY`
  и 403 у Codex; переподключение восстановило доступ.
- Полный режим меняет маршруты и DNS. Локальная сеть исключена из VPN.
  Поведение зависит также от существующего firewall; правила пользователя
  установщик не очищает. Настройки для NixOS и диагностика DNS описаны отдельно.
- Постоянного kill switch нет: при выключении полного VPN возвращается обычный
  интернет. Прокси-режим не изолирует сетевые возможности процесса.
- Проверены тесты генерации, переключения и восстановления состояния,
  наследования окружения, обработки 403 и установки файлов для systemd/runit.
  Собран Nix-пакет; сгенерированные конфиги приняты Mihomo 1.19.24.
  Новая переносимая служба пока **не проходила полный сетевой прогон на Void/Arch**.

## Разработка

```sh
python3 -m unittest discover -s tests -v
python3 install.py --backend runit --mihomo /usr/bin/mihomo --destdir /tmp/warp-stage
nix-build                     # При доступном <nixpkgs>
```

`--destdir` только раскладывает файлы в указанный каталог и не управляет
службами хоста. CI выполняет тесты без регистрации WARP, сети и ключей.
Файлы аккаунтов, конфиги, журналы и результаты сборки исключены через `.gitignore`.
