# Диагностика

## Codex отвечает 403

Сначала проверьте `warp-vpn status`. `warp=on` подтверждает туннель, но не
доступность OpenAI. `colo` обозначает узел Cloudflare, а `loc` — определённую
для запроса страну; они могут расходиться.

```sh
warp-vpn restart
```

После переподключения повторите сообщение в Codex. Команда `codex-warp`
сама делает одну такую попытку при 403 во время проверки перед запуском.
Переподключение прерывает другие текущие соединения через этот WARP.
Если отказ сохраняется, нужны дальнейшая проверка ответа сервера и, возможно,
другой узел. Обход всех ограничений сервиса или фиксированная страна не гарантируются.

## Сканы не находят узлы

Остановите службу перед сканированием с её ключами. Сначала запустите
WARPSCOUT непосредственно для просмотра диагностики:

```sh
warpscout scan -account "$HOME/.local/share/warp-vpn/warpscout-account.json" -p awg -exclude-country BY -best
```

Если регистрация не проходит, можно зарегистрировать устройства отдельно
с помощью поддерживаемого WARPSCOUT прокси и затем передать готовый файл
через `warp-vpn setup --account /путь/к/аккаунту.json`. Не запускайте
`warpscout register` поверх работающего аккаунта без необходимости:
это может ротировать ключи и сделать ранее установленные конфиги неактуальными.

## Прокси работает, полный VPN — нет

Сравните:

```sh
curl --noproxy '' --proxy http://127.0.0.1:10881 https://www.cloudflare.com/cdn-cgi/trace
curl --noproxy '*' https://www.cloudflare.com/cdn-cgi/trace
```

В прокси-режиме второй запрос должен идти обычным маршрутом. В полном режиме
оба должны проходить через WARP, за исключением локальных адресов.
Проверьте `/dev/net/tun`, конфликтующие VPN, порт 10881 и существующий firewall.
Если по числовому IP соединение работает, а по имени нет, исследуйте DNS
и reverse-path filtering для TUN. Не отключайте весь firewall для исправления
одного интерфейса.

## Программа идёт напрямую

Запускайте её через `warp-run`, либо включайте полный VPN. Переменные окружения
действуют только на новый процесс и его потомков. SSH и программы, которые
игнорируют HTTP-прокси, требуют отдельной настройки или полного VPN.
Git-настройка `http.proxy` и настройки самой программы могут переопределить
переменные окружения.

## Сбор диагностических данных

Начните с `warp-vpn doctor` и статуса службы, приведённого в инструкции к ОС.
В публичный issue достаточно добавить версию ОС, Mihomo, WARPSCOUT, режим,
`loc`/`colo`/`warp` и текст ошибки. Аккаунты, приватные конфиги и токены
авторизации для диагностики публиковать не нужно.
